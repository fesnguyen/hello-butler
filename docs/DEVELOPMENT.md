# DEVELOPMENT.md

# Hello Butler Development Guide

This document contains the practical setup for running, debugging, checking, and maintaining the Hello Butler repository during development.

Product behavior belongs in `docs/project_source_of_truth/PROJECT.md`. Engineering rules belong in `docs/project_source_of_truth/ENGINEERING.md`.

---

# Repository Layout

```text
hello-butler/
├── backend/
│   ├── .env
│   ├── .venv/
│   ├── alembic/
│   ├── app/
│   ├── alembic.ini
│   ├── pyproject.toml
│   └── uv.lock
├── docs/
├── .vscode/
│   └── launch.json
└── compose.yaml
```

`backend/.env` and `.vscode/launch.json` are local developer files and should not contain committed secrets.

# Environment Configuration

Create `backend/.env`:

```env
# Application
APP_ENV=development

# PostgreSQL
DATABASE_URL=postgresql+asyncpg://hello_butler:hello_butler@localhost:5433/hello_butler

# Authentication
JWT_SECRET=replace-with-a-random-secret-at-least-32-bytes
JWT_ALGORITHM=HS256
JWT_ISSUER=hello-butler
JWT_AUDIENCE=hello-butler-api
ACCESS_TOKEN_MINUTES=15
REFRESH_SESSION_DAYS=30
PASSWORD_MIN_LENGTH=8

# Google authentication
GOOGLE_OAUTH_CLIENT_ID=replace-with-google-oauth-client-id

# OpenAI / Butler
OPENAI_API_KEY=replace-with-openai-api-key
OPENAI_MODEL=replace-with-configured-model
BUTLER_DEFAULT_TIMEZONE=Asia/Ho_Chi_Minh
MORNING_BRIEF_DEFAULT_TIME=06:05
EVENING_PREPARATION_TIME=22:30
GOOD_NIGHT_SUMMARY_TIME=22:45

# Firebase Cloud Messaging (optional locally; required for server wake-up hints)
FIREBASE_PROJECT_ID=replace-with-firebase-project-id
FIREBASE_CREDENTIALS_PATH=/absolute/path/to/firebase-service-account.json
```

Generate a suitable local JWT secret with:

```bash
openssl rand -hex 32
```

Never commit real values for `JWT_SECRET`, `OPENAI_API_KEY`, Google credentials, access tokens, refresh tokens, or other private credentials.

The backend configuration loads `.env` through Pydantic Settings.

# Install Backend Dependencies

From the repository root:

```bash
cd backend
uv sync
```

`uv sync` creates/updates the local `.venv` and installs dependencies from `pyproject.toml` / `uv.lock`.

Normally do not manually activate the virtual environment. Prefer running commands through `uv run`.

# PostgreSQL with Docker Compose

PostgreSQL runs through the repository-level `compose.yaml`.

From the repository root:

```bash
docker compose up -d
```

Current development mapping:

```text
Host:      localhost:5433
Container: postgres:5432
Database:  hello_butler
User:      hello_butler
```

Check running services:

```bash
docker compose ps
```

View PostgreSQL logs:

```bash
docker compose logs postgres
```

Follow logs:

```bash
docker compose logs -f postgres
```

Stop containers:

```bash
docker compose stop
```

Stop and remove containers while keeping the named PostgreSQL volume:

```bash
docker compose down
```

Remove containers and persisted PostgreSQL development data:

```bash
docker compose down -v
```

Use `down -v` only when intentionally resetting the local database.

# Database Migrations

Run migrations explicitly. Migrations are not coupled to FastAPI startup.

From `backend/`:

```bash
uv run alembic upgrade head
```

Check the current migration:

```bash
uv run alembic current
```

View migration history:

```bash
uv run alembic history
```

Create a migration after an intentional SQLAlchemy schema change:

```bash
uv run alembic revision --autogenerate -m "describe schema change"
```

Always inspect autogenerated migrations before applying them.

Rollback one revision when deliberately needed:

```bash
uv run alembic downgrade -1
```

# VS Code Debugging

Keep the local debugger configuration at `.vscode/launch.json`:

```json
{
    "version": "0.2.0",
    "configurations": [
        {
            "name": "Hello Butler Backend",
            "type": "debugpy",
            "request": "launch",
            "module": "uvicorn",
            "args": [
                "app.main:app",
                "--host",
                "127.0.0.1",
                "--port",
                "8000"
            ],
            "cwd": "${workspaceFolder}/backend",
            "envFile": "${workspaceFolder}/backend/.env",
            "python": "${workspaceFolder}/backend/.venv/bin/python",
            "justMyCode": true
        }
    ]
}
```

Do not add `--reload` to the debugger configuration by default. Uvicorn reload creates a separate process and makes breakpoint behavior less predictable.

Recommended first breakpoint for following the Butler request flow:

```text
backend/app/api/butler.py
```

Then call `POST /api/butler/talk` and step through authentication, application orchestration, LangGraph, AI reasoning, deterministic mutation, persistence, and response construction.

# Authentication During Manual Development

Register or log in first:

```text
POST /api/auth/register
POST /api/auth/login
```

The response contains:

```json
{
    "access_token": "...",
    "refresh_token": "...",
    "token_type": "bearer",
    "expires_in": 900
}
```

Protected requests use the access token:

```http
Authorization: Bearer <access_token>
```

The refresh token is used only with the refresh/logout session flow, not as the Bearer token for normal protected APIs.

Example Butler request:

```bash
curl -X POST 'http://127.0.0.1:8000/api/butler/talk' \
  -H 'Authorization: Bearer YOUR_ACCESS_TOKEN' \
  -H 'Content-Type: application/json' \
  -d '{
    "interaction_mode": "talk",
    "message": "What do I have today?"
  }'
```

# Morning Brief End-to-End Test

Start PostgreSQL and the backend, apply the current migration, then register or
log in. Put the returned access token in a shell variable without committing it:

```bash
export BUTLER_ACCESS_TOKEN='paste-development-access-token'
```

Prepare today so its events are visible immediately. Set the Morning Brief time
two or three minutes ahead using local `HH:MM:SS` time. The override is accepted
only when `APP_ENV` is not `production`; production accepts the normal tomorrow
target only:

```bash
export TARGET_DATE="$(date +%F)"
export MORNING_BRIEF_TIME="$(date -d '+3 minutes' +%T)"

curl -X POST 'http://127.0.0.1:8000/api/planning/prepare' \
  -H "Authorization: Bearer $BUTLER_ACCESS_TOKEN" \
  -H 'Content-Type: application/json' \
  -d "{\"target_date\":\"$TARGET_DATE\",\"morning_brief_time\":\"$MORNING_BRIEF_TIME\"}"
```

Omit `target_date` and `morning_brief_time` to exercise normal tomorrow planning
and context-derived/default Morning Brief timing. Run the request twice, then
inspect the authoritative snapshot; the plan, planner keys, and protected
commitments should not duplicate:

```bash
curl "http://127.0.0.1:8000/api/sync/daily-plan/$TARGET_DATE" \
  -H "Authorization: Bearer $BUTLER_ACCESS_TOKEN"
```

For a physical phone, set `BACKEND_BASE_URL` to the backend machine's LAN URL,
and provide these Gradle properties through the user-level
`~/.gradle/gradle.properties` file when testing FCM:

```properties
FIREBASE_APPLICATION_ID=replace-with-android-firebase-app-id
FIREBASE_API_KEY=replace-with-firebase-api-key
FIREBASE_PROJECT_ID=replace-with-firebase-project-id
FIREBASE_SENDER_ID=replace-with-firebase-sender-id
```

Install the app and sign in. Synchronization runs automatically; toolbar Refresh
is only a recovery/development action. Grant Android's
**Alarms & reminders** special access when exact timing is required; without it,
WorkManager posts a potentially delayed **Listen** notification. Tap Listen to
start offline speech; this fallback does not provide unattended playback.
Enable notifications and install an offline TTS voice. Confirm the generated
events appear on the Main Screen, put the app in the background or swipe it away,
and wait for local TTS. The foreground notification and Main Screen expose Stop
while Butler speaks. Stop the backend after synchronization to verify playback
uses Room only. Do not force-stop the app in system settings because Android then
suppresses its alarms and work until the next manual launch.

Useful device checks:

```bash
adb shell dumpsys alarm | grep hellobutler
adb shell dumpsys jobscheduler | grep hellobutler
adb logcat | grep -i hellobutler
```

The lifecycle now includes automatic 22:30 preparation, durable bidirectional
event sync, FCM wake-up hints, and offline Morning Brief / Good Night Summary
speech. Per-user timezones and user-configurable lifecycle times remain later
product work; current server scheduling uses `BUTLER_DEFAULT_TIMEZONE`, while
Android scheduling follows the device timezone. These zones **must match** on
every device; use `BUTLER_DEFAULT_TIMEZONE=Asia/Ho_Chi_Minh` for Vietnam devices
using that zone. Keep server evening preparation at 22:30 to match the client.

See [daily lifecycle fix review](DAILY_LIFECYCLE_FIX_REVIEW.md) for implementation
decisions, automated coverage, outstanding device gates and reproduction steps.

# Ruff

Check lint rules:

```bash
cd backend
uv run ruff check .
```

Format:

```bash
uv run ruff format .
```

Format and then lint:

```bash
uv run ruff format . && uv run ruff check .
```

Prefer fixing the underlying issue rather than broadly disabling Ruff rules.

# Pyright

Run strict static type checking:

```bash
cd backend
uv run pyright
```

Keep suppressions local and justified when an external library has incomplete or incorrect typing.

---

# Standard Backend Verification

For a normal backend change:

```bash
cd backend
uv sync
uv run ruff format .
uv run ruff check .
uv run pyright
uv run alembic current
```

If the schema changed:

```bash
uv run alembic upgrade head
```

Then run the application and manually verify the affected endpoint/workflow.

Automated tests are not required by default during the current early-development stage unless a concrete implementation need justifies one.

# Development Principle

Keep the normal path simple:

```text
Docker Compose
    ↓
PostgreSQL

uv
 ↓
FastAPI
 ↓
Alembic / SQLAlchemy
 ↓
Butler application
 ↓
LangGraph
 ↓
OpenAI Responses API
```

Use Docker for infrastructure, run the backend directly through `uv` during normal development, keep migrations explicit, and keep debugging configuration local.
